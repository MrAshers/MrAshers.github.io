# 双分支部署

> 原来看的博客教程提交到 github 上的只有网页的静态页面，没有把博客原本的 markdown 内容提交上去，故考虑双分支部署。
> 参考博客 [hexo + yilia主题优化及双分支部署](https://www.cnblogs.com/codecheng99/p/12380700.html#%E4%BA%8C%E5%B0%86hexo%E9%83%A8%E7%BD%B2%E5%88%B0github%E4%B8%8A%E9%9D%A2%E5%AE%9E%E7%8E%B0%E5%8F%8C%E5%88%86%E6%94%AF%E9%83%A8%E7%BD%B2)

由于版本原因，其他教程上 main 可能说的是 master，不影响，新版本就是 main 。

```sql
mrashers.github.io
-- main     部署分支：主要存放生成的静态文件，用于部署到github pages
-- blog     写作分支：主要存放 hexo 环境配置、博客（md）
```

## 1. 部署 main 分支

### 1.1 指定 hexo 部署的方式、仓库、分支

修改 hexo 根目录下的 `_config.yml`

```yml
# 部署到 github 的仓库
# Deployment
# Docs: https://hexo.io/docs/deployment.html
deploy:
  type: git
  repository: https://github.com/mrashers/mrashers.github.io.git
  branch: main
```

### 1.2 为项目添加说明 `README.md`

你可以把 `README.md` , `LICENSE` （许可证）等文件放在 /source/ 目录下，该目录的文件可以上传到github根目录；`hexo g` 是将 /source//.md 所有文件渲染成 html 文件（如果没有设置跳过渲染的话），然后放到对应的 /public/ 目录下；而对于其他文件，直接复制到对应文件夹下。

设置跳过渲染 `README.md` ，需要修改 hexo 根目录下的 `_config.yml`。

```yml
# hexo g 会默认将所有 md 文件转换成（渲染成）HTML文件放到 public 文件夹中；加上这句话的意思就是告诉 hexo 的解析器，跳过渲染(skip_render)README.md文件。
skip_render: 
 - 'README.md'
```

如果不设置该属性，`READ.md` 文件会被转换成 `READ.html` 文件，同理你可以通过该配置跳过渲染你不希望 hexo 渲染的 md 文件。

### 1.3 把 main 分支部署到 github 的 main 分支

如果有修改配置文件，最好都进行重新编译。

```bash
hexo clean      # 清理文件
hexo g          # 生成静态网页
# hexo s        # 查看网页预览
hexo d          # 提交网页
```

## 2. 部署 blog 分支

该分支名可自定义。

### 2.1 在 Hexo 根目录打开 git 命令行，初始化仓库

在hexo根目录下新建仓库，用于管理写作分支（之前的部署到 github 的为部署分支）。

```bash
git init
git remote add origin https://github.com/mrashers/mrashers.github.io.git
```

### 2.2 忽略一些不需要备份的文件

修改根目录下的 `.gitignore` ，`.gitignore` 的原内容：

```yml
.DS_Store
Thumbs.db
db.json
*.log
node_modules/
public/
.deploy*/
_multiconfig.yml
```

在后面增加以下内容，用来忽略原来的主题文件：

```yml
# ignored the useless themes
/themes/landscape/
```

### 2.3 删除 `/themes/yilia/.git`文件夹

`/themes/yilia` 里面也有一个仓库，这涉及到 git 仓库下的子仓库问题（之前有用过其他办法没解决。。。）默认情况下是不将该子仓库介入到外层仓库的，但是我们要备份 yilia 主题的配置文件，所以删除该子仓库，即删除 `/themes/yilia/.git` 文件夹。

### 2.4 创建 blog 分支

创建一个分支存放写作内容，方便同步到同一个仓库的不同分支。

添加、提交。

```bash
git add .
git commit -m "init the blog"
```

创建分支，并同步到 github 的 blog 分支。

```bash
git branch blog
git checkout blog
git push origin blog
```

### 2.5 github 上把 blog 分支设置为默认分支

可设置该分支为默认分支，这样以后仓库主页显示的就是 blog 分支，而且拉取（或者克隆）的时候拉取的就是 blog 分支，而不是原来默认的 main 分支。

### 2.6 实现双分支部署

每次写完博客要同时同步到该仓库的不同分支上，以实现真正的同步（备份）。

```bash
# Writing
# 同步到master分支
hexo clean
hexo generate       # 也可以直接 hexo g
hexo deploy         # 也可以直接 hexo d

# 手动同步到blog分支上
git add .
git commit -m "提交信息"
git push origin blog # 如果设置了blog为默认分支，可以直接git push
```

## 1. 前言

对于目前大陆用户而言，想要直接访问用 github 托管的个人博客不是件容易的事，为解决网络不可达问题，可以采用 CDN(content delivery network) 将网页内容分发到全球各地的服务器上，同时缩短网站加载时间。

国内大部分 CDN 服务收费，故考虑 [cloudflare](https://www.cloudflare.com/)。
cloudflare 作为全球最大的网络服务提供商，提供免费的 cdn 服务，虽然 cdn 节点都在国外，但还是比直接访问 github.io 要快的多。

## 2. 准备

使用 cloudflare 的 cdn 服务需要我们拥有一个可配置的域名。
我在[阿里云](https://www.aliyun.com/)购买了一个 `.space` 的后缀的域名，10 年价格也只要 188，记得实名认证。

# ❗❗❗可能出现的问题

## 使用 CloudFlare 导致网站 `重定向的次数过多`

**解决方案：**

在 CloudFlare 的 `SSL/TLS 菜单` 里将 `SSL/TLS 加密模式` 设置为 `完全（Strict）` 即可。

## Valine 评论区提示 `code 403访问被api域名白名单拒绝请检查你的安全域名设置`

**解决方案：**

在 LeanCloud 的`应用` --> `设置` --> `安全中心` --> `Web安全域名` 中添加新的自定义域名即可解决该问题。
此处【新的自定义域名】指的是：你的博客的访问域名。安全域名的具体添加方式根据 LeanCloud 的要求添加即可。
