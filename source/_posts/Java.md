## java中集合类型有哪些？   
Java 中常见的集合类型包括：  
1. `ArrayList`：基于动态数组实现的列表，支持动态增长。   
2. `LinkedList`：基于双向链表实现的列表，适合频繁插入和删除操作。    
3. `HashSet`：基于哈希表实现的集合，不允许重复元素，不保证顺序。    
4. `LinkedHashSet`：基于哈希表和双向链表实现的集合，可以保持元素插入顺序。    
5. `TreeSet`：基于红黑树实现的有序集合，元素按照自然顺序或者指定比较器排序。    
6. `HashMap`：基于哈希表实现的映射，键值对无序。   
7. `LinkedHashMap`：基于哈希表和双向链表实现的映射，可以保持插入顺序或者访问顺序。    
8. `TreeMap`：基于红黑树实现的有序映射，键按照自然顺序或者指定比较器排序。    
9. `PriorityQueue`：基于堆实现的优先队列，可以按照元素的优先级进行访问。    

除了以上列出的集合类型外，Java 还提供了一些特殊用途的集合，如`WeakHashMap`、`EnumSet`、`EnumMap` 等。在 Java的集合框架中，还有一些接口如`List`、`Set`、`Map`等，它们分别代表列表、集合和映射的抽象概念，具体的实现类可以根据需求进行选择。

## java的垃圾回收机制是什么，什么时候使用？    
Java 的垃圾回收机制是一种自动内存管理系统，它负责在运行时自动识别和释放不再被程序引用的内存，以防止内存泄漏和提高程序的性能。   
Java 中的垃圾回收机制基于以下几个关键概念：   
1. **垃圾收集器（Garbage Collector）：** Java 垃圾收集器是一组在 Java 虚拟机中运行的线程，负责回收不再被引用的对象的内存。Java 的垃圾收集器采用分代垃圾回收策略，将内存分为年轻代和老年代，以更有效地管理不同生命周期的对象。    
2. **引用（Reference）：** Java 提供了不同类型的引用，如强引用、软引用、弱引用和虚引用，用于控制对象被垃圾回收的条件。强引用是最常见的引用类型，而软引用、弱引用和虚引用则提供了更灵活的控制选项。     
3. **垃圾回收算法：** Java 虚拟机采用不同的垃圾回收算法，如标记-清除、复制、标记-整理等。这些算法用于在不同情况下更高效地回收垃圾对象。  

垃圾回收机制是自动进行的，无需程序员显式地进行干预。垃圾回收器会周期性地检查程序中的对象，并识别那些不再被引用的对象，然后释放它们占用的内存。  

一般来说，程序员**无需显式**地触发垃圾回收，因为 Java 虚拟机会在需要时自动进行。然而，在某些特殊情况下，可以使用 `System.gc()` 或 `Runtime.getRuntime().gc()` 来请求垃圾回收，但这只是一个建议，并不保证会立即执行垃圾回收。    
在大多数情况下，信任垃圾回收机制自动管理内存是明智的选择。手动触发垃圾回收通常是出于性能调优的目的，但在正常情况下，不建议频繁使用。

## MD5的优缺点。  
MD5（Message Digest Algorithm 5）是一种常用的哈希函数，用于生成固定长度（128位）的哈希值，通常以 32 个十六进制字符的形式表示。虽然 MD5 在过去广泛应用于数据完整性校验和密码存储，但在现代应用中，MD5 已经被认为是不安全的，主要是因为其存在以下一些优缺点：  
- **优点：**  
    - **快速计算：** MD5 是一种快速的哈希算法，对于大多数应用而言，生成 MD5 哈希值的速度相对较快。  
    - **固定长度输出：** MD5 生成的哈希值长度是固定的（128位或32个字符），这使得它适用于需要固定长度摘要的场景。  
- **缺点：**  
    - **易碰撞性：** MD5 存在碰撞问题，即不同的输入可能会产生相同的哈希值，这降低了其在安全性要求较高场景的可靠性。攻击者可以通过特定技术生成具有相同 MD5 哈希值的不同输入，这对于密码破解等攻击是危险的。    
    - **不可逆性：** MD5 是单向哈希函数，无法从哈希值还原出原始数据。这使得它适用于密码存储等场景，但也意味着无法通过哈希值反向获取原始数据。    
    - **已被破解：** MD5 已经被广泛破解，通过预先计算大量可能的输入值（彩虹表攻击）、使用碰撞攻击等方法，使得它不再安全可靠。  
    - **不适用于安全场景：** 由于易碰撞性和已被破解的问题，MD5 不再适用于安全性要求较高的场景，如加密、数字签名等。  

综合来看，由于 MD5 的缺陷，现代应用中更推荐使用安全性更高的哈希函数，如SHA-256 或 SHA-3，以满足更高的安全要求。   

## `1 * 0.3 == 0.3`返回的是`true`还是`false`？   
在绝大多数编程语言中，`1 * 0.3`的结果会是一个浮点数，而浮点数在计算机中存储时可能会有精度限制。因此，比较浮点数时可能会遇到精度误差。   
在大多数情况下，`1 * 0.3`的结果可能是接近 0.3 但不完全等于 0.3。因此，表达式 `1 * 0.3 == 0.3`在实际执行时可能返回 `false`，这是由于浮点数精度问题导致的。   
为了避免由于浮点数精度问题导致的比较错误，通常建议使用某个阈值进行比较，例如：   
```java
epsilon = 1e-10
result = 1 * 0.3
print(abs(result - 0.3) < epsilon)  # 返回 True 或 False，根据精度是否满足
```
在上面的例子中，`epsilon`是一个很小的阈值，用于判断两个浮点数是否足够接近。这样可以避免由于精度误差而导致的比较问题。 

## `i++`是线程安全的吗？  
`i++`操作本身是一个简单的自增操作，但在多线程环境中使用时可能***不是线程安全***的。这是因为`i++`操作实际上包括了读取、增加和写回三个步骤，而这些步骤在多线程环境中可能会发生交叉执行，导致**竞态条件（Race Condition）**。   
考虑以下代码：  
```java
int i = 0;

// 在多线程环境中可能不是线程安全的
i++;
```
在这个简单的例子中，如果两个线程同时执行`i++`操作，可能会导致竞态条件。例如，线程A读取`i`的值，然后线程B也读取`i`的值，两者都增加了1，然后分别写回，结果`i`的增加只有1而不是预期的2。

要使`i++`操作在多线程环境中是线程安全的，可以使用同步机制，例如使用`synchronized`关键字或使用原子操作类，如`AtomicInteger`：    
```java
private static AtomicInteger i = new AtomicInteger(0);

// 线程安全的自增操作
i.incrementAndGet();
```

使用`AtomicInteger`类的`incrementAndGet()`方法可以保证原子性，确保在多线程环境中递增操作是线程安全的。   

## Map的遍历有哪几种方式？   
在 Java 中，可以使用不同的方式来遍历 `Map`。以下是一些常见的遍历方式：  
1. **使用 EntrySet 遍历：**   
    通过获取 `entrySet()`，然后遍历 `Map.Entry` 对象。   
    ```java
    Map<String, Integer> map = new HashMap<>();

    for (Map.Entry<String, Integer> entry : map.entrySet()) {
    String key = entry.getKey();
    Integer value = entry.getValue();
    // 处理 key 和 value
    }
    ```
2. **使用 keySet 遍历：**  
    通过获取 `keySet()`，然后遍历键，再通过键获取对应的值。   
    ```java
    Map<String, Integer> map = new HashMap<>();
    
    for (String key : map.keySet()) {
    Integer value = map.get(key);
    // 处理 key 和 value
    }
    ```
3. **使用 forEach 遍历（Java 8+）：**  
    使用 Java 8 的 forEach 方法和 Lambda 表达式。   
    ```java
    Map<String, Integer> map = new HashMap<>();
    
    map.forEach((key, value) -> {
    // 处理 key 和 value
    });
    ```
4. **使用 Iterator 遍历：**  
    使用迭代器遍历 `Map`。   
    ```java
    Map<String, Integer> map = new HashMap<>();
    Iterator<Map.Entry<String, Integer>> iterator = map.entrySet().iterator();

    while (iterator.hasNext()) {
        Map.Entry<String, Integer> entry = iterator.next();
        String key = entry.getKey();
        Integer value = entry.getValue();
        // 处理 key 和 value
    }
    ```

以上是一些常见的遍历方式，选择哪种方式取决于具体的需求和代码风格。在 Java 8 及更高版本中，使用 *`Lambda`表达式* 的`forEach`方法可以使代码更简洁。   

## `==`和`equals`的区别？   
在 Java 中，`==` 和 `equals()` 是两个不同的比较方式，它们的主要区别在于比较的对象和比较的方式：  
**1. `==` 运算符：**  
- 用于比较两个对象的引用是否指向相同的内存地址。   
- 如果比较的是基本数据类型，比较的是值是否相等。   
- 对于对象引用，比较的是对象的地址，即对象是否为同一实例。   
- 在基本数据类型和引用类型中，`==` 的行为是不同的。  
```java
String str1 = new String("Hello");
String str2 = new String("Hello");

System.out.println(str1 == str2);  // false，因为两个对象的引用不同
```

**2. `equals()` 方法：**  
- `equals()` 是 `Object` 类的方法，用于比较两个对象的内容是否相等。  
- 通常需要被子类重写以提供特定类型的比较逻辑。  
- 在 `Object` 类中，`equals()` 默认实现是使用 `==` 运算符，因此它比较的仍然是引用是否相同。  
```java
String str1 = new String("Hello");
String str2 = new String("Hello");

System.out.println(str1.equals(str2));  // true，因为重写了 String 类的 equals 方法，比较的是内容
```

在一些类库中，如 `String` 类，`equals()` 被重写以比较对象的内容而不是引用地址。但在一些自定义类中，如果没有重写 `equals()` 方法，它默认的行为仍然是比较引用地址。   
总体来说，对于自定义类，为了实现对象内容的比较，通常需要重写 `equals()` 方法，并根据业务需求定义比较的规则。   

## `final`的作用？  
- 修饰类：表明该类不可被继承，类中的所有成员方法都隐式的被指定为`final` 方法，成员变量则可定义为`final`，也可不定义为`final`。  
- 修饰方法：用`final` 修饰方法的原因有两个：   
    - 锁定这个方法，防止任何继承类修改它的含义；  
	- 提高效率：在方法前面添加`final` 进行修饰可以提高效率，其原理是基于内联/内嵌（inline）机制，它会使你在调用`final` 方法时，直接将方法的主体插入到调用处，从而省去调用函数所花费的开销。但是如果方法过于庞大或者其中有循环的话，这种提高效率的方法可能会失效。   
- 修饰变量：`final` 对变量的修饰的作用，是防止变量值的改变；  
	- 如果修饰的是基本类型数据变量，则该变量的值不能发生改变；  
	- 如果修饰的是引用类型数据变量，则该变量不会内二次初始化；

## 普通类和抽象类的区别？  
### 抽象类   
- 含有抽象方法的类就叫抽象类。而抽象方法就是被`abstract`修饰的方法，这个方法可以没有具体的实现。   
- 在抽象类的子类中必须对抽象方法进行重写，当其子类为抽象类时，可以不重写抽象方法，但在其子类中一旦有普通类，则必须重写父类继承的所有抽象方法。   
- 抽象类不可以实例化。抽象类的构造方法作用为初始化子类对象。   
- 抽象类存在的意义就是为了被继承。   
- 抽象类中的普通属性和普通方法都需要用子类的对象去调用。  

### 普通类   
- 普通类可以实例化，实例化后可以调用自己类中的属性和方法或父类的方法和属性。   
- 普通类的构造方法中必须要调用父类的构造方法。   
- 如果普通类继承了抽象类，那么必须要重写所有父类的抽象方法。   
- 普通类存在的意义就是实例化。   

## 接口和抽象类的区别？   
### 相同点   
1. 都不能被实例化。    
2. 接口的实现类或抽象类的子类都只有实现了接口或抽象类中的方法后才能实例化。   

### 不同点   
1. 接口只有定义，不能有方法的实现，java 1.8中可以定义`default`方法体，而抽象类可以有定义与实现，方法可在抽象类中实现。   
2. 实现接口的关键字为`implements`，继承抽象类的关键字为`extends`。一个类可以实现多个接口，但一个类只能继承一个抽象类。所以，使用接口可以间接地实现多重继承。   
3. 接口强调特定功能的实现，而抽象类强调所属关系。   
4. 接口成员变量默认为`public static final`，必须赋初值，不能被修改；其所有的成员方法都是`public`、`abstract`的。抽象类中成员变量默认`default`，可在子类中被重新定义，也可被重新赋值；抽象方法被`abstract`修饰，不能被`private`、`static`、`synchronized`和`native`等修饰，必须以分号结尾，不带花括号。   

## HashMap的实现原理？   
HashMap是一种用于存储键值对的数据结构，它提供了快速的查找、插入和删除操作。在Java中，HashMap是基于哈希表（Hash Table）实现的。以下是HashMap的主要实现原理：   
**1. 哈希函数（Hash Function）：**  
- 当你往HashMap中插入一个键值对时，首先会使用哈希函数计算键的哈希码。哈希码是一个32位的整数，用于映射键到哈希表的索引。  

**2. 数组（Array）：**  
- HashMap内部维护一个数组，这个数组被称为桶（buckets）或者槽（slots）。每个槽可以存放一个链表或红黑树。  

**3. 索引计算：**  
- 利用哈希码和数组的长度，计算出键在数组中的索引。这通常是通过对哈希码进行取模运算来实现的。例如，如果数组长度为N，那么索引 = 哈希码 % N。 

**4. 冲突处理：**  
- 不同的键可能产生相同的哈希码，这就是哈希冲突。HashMap使用链表和红黑树来处理冲突。   
- 如果多个键的哈希码映射到同一个索引位置，这些键的键值对会以链表形式存储在该位置。   
- 当链表长度较长时，为了维护查找效率，HashMap会将链表转换为红黑树。 

**5. 链表和红黑树：**  
- 在Java 8中，当链表长度达到一定阈值时，HashMap会将链表转换为红黑树。这样可以提高在链表中进行查找、插入和删除操作的效率，因为红黑树的时间复杂度为O(log n)。 

**6. 扩容：**  
- 当HashMap中的元素数量超过容量的一定比例（负载因子），HashMap会进行扩容。扩容是为了保持哈希表的性能。扩容时，数组长度会变为原来的两倍，并且所有的键值对会重新计算索引并放入新的数组中。  

**7. 迭代顺序：**  
- 在HashMap中，元素的顺序是不保证的，因为它是根据哈希码和数组长度计算索引的。如果需要有序的集合，可以考虑使用LinkedHashMap，它保留了元素的插入顺序。  

总的来说，HashMap通过哈希表实现了快速的键值对操作，但在处理冲突、扩容等方面有一些复杂的实现细节。  

## ArrayList和LinkedList的区别？   
- ArrayList基于动态数组实现的非线程安全的集合；LinkedList基于链表实现的非线程安全的集合。   
- 对于随机index访问的`get` 和`set` 方法，一般ArrayList的速度要优于LinkedList。因为ArrayList直接通过数组下标直接找到元素；LinkedList要移动指针遍历每个元素直到找到为止。   
- 新增和删除元素，一般LinkedList的速度要优于ArrayList。因为ArrayList在新增和删除元素时，可能扩容和复制数组；LinkedList实例化对象需要时间外，只需要修改指针即可。   
- LinkedList集合不支持高效的随机随机访问（RandomAccess）。   
- ArrayList的空间浪费主要体现在在list列表的结尾预留一定的容量空间，而LinkedList的空间花费则体现在它的每一个元素都需要消耗相当的空间。   

## Array和ArrayList的区别？ 
- array可以包含基本类型和对象类型，arraylist只能包含对象类型。   
- array大小是固定的，arraylist的大小是动态变化的。arraylist提供了更多的方法和特性，比如添加全部`addAll()` ,删除全部`removeAll()` ,返回迭代器`iterator()` 等等。   
- 对于基本类型数据，集合使用自动装箱来减少编码工作量。但是，当处理固定大小的基本数据类型的时候，这种方式相对比较慢。   
- 适用场景：   
	- 如果想要保存一些在整个程序运行期间都会存在而且不变的数据，我们就可以把它放进一个全局数组里，但是我们如果只是单纯的想要以数组的形式保存数据，而不对数据进行增加等操作，只是方便我们进行查找的话，那么我们就选择arraylist。   
	- 但是如果我们需要对数据进行频繁的移动或者删除，或者处理的是超大的数据量，那么arraylist效率就很低了，这时候我们可以考虑linkedlist。

> **方法一：继承于Thread类**：   
>> 步骤：  
>> 1. 创建一个继承于Thread类的子类  
>> 2. 重写Thread类的run() --> 将此线程执行的操作声明在run()中  
>> 3. 创建Thread类的子类的对象 
>> 4. 通过此对象调用start()执行线程    

> **方法二：实现runnable接口**：   
>> 步骤：  
>> 1. 创建一个实现了Runnable接口的类   
>> 2. 实现类去实现Runnable中的抽象方法：run()    
>> 3. 创建实现类的对象   
>> 4. 将此对象作为参数传递到Thread类的构造器中，创建Thread类的对象    
>> 5. 通过Thread类的对象调用start()  
>> 	1. 启动线程  
>> 	2. 调用当前线程的run()–>调用了Runnable类型的target的run()

> **方法三：实现Callable接口**：  
>> 步骤：
>> 1. 创建一个实现Callable的实现类
>> 2. 实现call方法，将此线程需要执行的操作声明在call()中
>> 3. 创建Callable接口实现类的对象
>> 4. 将此Callable接口实现类的对象作为传递到FutureTask构造器中，创建FutureTask的对象 
>> 5. 将FutureTask的对象作为参数传递到Thread类的构造器中，创建Thread对象，并调用start()
>> 6. 获取Callable中call方法的返回值   

> **方法四：使用线程池**：
>> 步骤：
>> 1. 以方式二或方式三创建好实现了Runnable接口的类或实现Callable的实现类
>> 2. 实现run或call方法
>> 3. 创建线程池
>> 4. 调用线程池的execute方法执行某个线程，参数是之前实现Runnable或Callable接口的对象   

> **方法五：使用匿名类**：  
>> 
```java
Thread thread = new Thread(new Runnable() {
    @Override
    public void run() {
        // 线程需要执行的任务代码
        System.out.println("子线程开始启动....");
        for (int i = 0; i < 30; i++) {
            System.out.println("run i:" + i);
        }
    }
});
thread.start();
```

>> 或者
```java
new Thread(() -> {
	System.out.println(Thread.currentThread().getName() + "\t上完自习，离开教室");
}, "MyThread").start();
```
